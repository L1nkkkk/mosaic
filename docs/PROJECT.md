# Mosaic · 拼页：项目介绍

Mosaic 是用独立模块搭建个人页面的轻量应用。同一份内容可以组成对外展示的 Public 页面，也可以组成只有站点主人能查看的 Private 页面。站点主人在编辑台直接点击画布上的模块编辑内容、拖动调整顺序和大小，再决定哪些内容公开；模块多时可搜索定位，无需常驻侧栏。

本文对应 Mosaic 0.9.x。开发一个普通展示模块，推荐使用自己的 `definition.js`、`client.js` 和 `style.css`（旧 `index.js` 继续兼容），不需要修改核心模块列表或拖拽代码。

[返回 README](../README.md) · [模块开发手册](MODULES.md) · [HTTP 接口参考](HTTP-API.md)

## 适合做什么

可以用它搭建个人主页、作品入口、链接集合、近况公告，以及需要登录才能查看的服务状态面板。当前内置介绍、手记、链接清单、服务器状态、Bot 状态和代理节点、待办清单、WebGL 色场、天气、音乐、书单、访客来源和照片卡片十三种模块。

一个模块类型可以添加多个实例，每个实例有自己的内容、公开范围和尺寸。每页最多 30 个模块；模块按用户指定的顺序排布，窄屏时自动加宽和换行。

## 四个入口

以下路径都相对于站点根路径；部署在 `/mosaic` 时，编辑台就是 `/mosaic/edit`。

| 入口 | 使用者 | 读取什么 |
| --- | --- | --- |
| `/` 或 `/public` | 所有访客 | 已发布且未隐藏的 Public 模块 |
| `/private` | 登录的站点主人 | 全部已保存草稿，包括 Private、Public、隐藏和未发布模块 |
| `/lab` | 登录的站点主人 / 模块作者 | 独立测试尺寸、资源、动画与实验数据，不写正式页面 |
| `/edit` | 登录的站点主人 | 编辑草稿、实时预览、拖拽排序与缩放、保存与发布 |

编辑器里的改动先保留在当前浏览器页面。**保存**更新私人页；**发布**把草稿作为新的公开版本。把已公开模块改为 Private 并保存，会立即限制同一实例的公开访问。隐藏、移除或普通内容修改，需要发布才会更新公开页。

Public 的过滤发生在服务端，登录后访问 Public 接口仍然只返回公开内容。服务器和 Bot 状态模块声明了 `privateOnly: true`，服务端会拒绝将它们设为 Public。

## 核心与模块怎样分工

| 核心负责 | 模块负责 |
| --- | --- |
| 发现模块、装载代码和样式 | 声明名称、默认数据、推荐尺寸 |
| 登录、服务端权限、草稿和发布存储 | 校验并规范化自己的内容字段 |
| 整页响应式布局、卡片外框、排序和缩放 | 渲染卡片内部内容，适应分配到的宽高 |
| 编辑台的通用操作和保存状态 | 提供自己的编辑控件 |
| 共享动画时钟、尺寸 / 可见状态通知、资源刷新与清理 | 通过可选的 `load()` 读取已有接口 |

模块通过服务端 `meta / validate` 与浏览器 `mount / edit / load` 接口接入；旧 `render()` 有兼容适配器。核心按稳定实例 ID 管理生命周期，排序、缩放和资源更新复用已有实例；删除、切换范围后不再显示或离开页面时清理。核心不需要认识模块里的标题、链接列表或其他业务字段。

布局使用 12 列网格，可切换瀑布流。模块声明推荐占列数和舒适宽度；用户可以覆盖某个实例的宽度与高度。核心负责外框和换行，模块通过 CSS 容器查询适应自己的实际尺寸。内容过长时，固定高度的外框提供滚动。

## 技术结构

应用使用 Node.js 24 和浏览器原生 JavaScript 模块，没有第三方运行依赖和前端打包步骤。后端提供 JSON 接口及静态文件，前端负责展示和编辑。开发时需要支持 CSS 容器查询、`ResizeObserver` 和原生 ES modules 的现代浏览器。

```text
mosaic/
├── modules/                 模块类型；definition.js + client.js，或旧 index.js；以及 style.css
│   ├── note/                简单文本模块的实际范例
│   ├── links/               列表编辑和安全外链范例
│   ├── server-status/       私人实时数据模块范例
│   ├── todo/                交互保存与稳定 DOM 范例
│   └── shader/              WebGL 尺寸、动画与清理范例
├── web/
│   ├── app.js               页面加载、编辑器、模块渲染与资源刷新
│   ├── shell.js             共用导航、设备外观偏好与移动端菜单
│   ├── appearance.js        全站背景设置、上传前压缩
│   ├── theme.css            主题变量、应用外壳及响应式样式
│   ├── assets/              随代码部署的山景背景
│   ├── runtime.js           持久实例、共享帧调度与资源清理
│   ├── lab.js               独立模块实验台
│   ├── ui.js                文本校验、转义、链接和表单工具
│   ├── layout.js            尺寸契约与容器排布
│   ├── arrange.js           拖拽排序、缩放及键盘操作
│   └── styles.css           整页样式和模块外框
├── server/
│   ├── modules.js           模块发现、页面校验和公开范围过滤
│   ├── app.js               HTTP 路由、权限检查和静态资源
│   ├── store.js             JSON 存储、原子写入、保存版本检查
│   ├── auth.js              密码校验与会话
│   └── status.js            私人状态字段白名单
├── examples/                hello-card 静态模板、live-card 交互模板
├── docs/                    开发者文档
├── test/                    应用、权限、模块与布局测试
├── deploy/                  自动更新和宿主机状态采集
└── data/                    本地运行数据，不提交到 Git
```

`DATA_DIR/content.json` 保存草稿、发布版本和递增的 `revision`。写入采用原子替换，版本冲突返回错误，避免两个编辑窗口静默覆盖。已有内容无法读取时应用拒绝启动，保留原始文件。

## 本地启动

在终端执行，先确认 Node.js 为 24 或更新版本：

```sh
git clone https://github.com/L1nkkkk/mosaic.git
cd mosaic
node scripts/setup.js
node --env-file=.env server/index.js
```

第一次设置生成 `.env` 并显示本地管理密码。已有 `.env` 时跳过设置命令，它不会覆盖配置。不需要执行 `npm install`。

打开 `http://localhost:3000/`；在 `http://localhost:3000/edit` 登录编辑。没有宿主机状态采集文件时，服务器和 Bot 模块显示等待采集，这是正常的本地状态。

需要监听代码变化时，使用下面的启动方式；增加新的模块目录后应重新启动进程，修改前端文件后刷新浏览器：

```sh
node --env-file=.env --watch server/index.js
```

运行仓库检查：

```sh
npm test
npm run check
npm run test:browser  # 需要 Chrome / Chromium
```

下一步照着[模块开发手册](MODULES.md)复制模板，在编辑台添加自己的第一个模块。

## 从开发到上线

模块代码随仓库发布，页面内容在编辑台保存和发布。两者是独立流程：部署代码会增加可用的模块类型，不会自动向已有页面添加实例。

当前仓库推送 `main` 后，GitHub Actions 运行测试并构建公开容器镜像。服务器定期检查镜像，用现有内容副本验证候选版本后更新；持久化内容独立挂载。具体安装、配置、备份和回退步骤见 [README](../README.md)。

提交新模块时，应包含模块源码、必要的内容校验测试，以及模块特有的配置说明。修改旧模块时，必须继续读取已有草稿和发布内容，或明确提供迁移方案。

## 当前边界

- 单管理员、单应用进程、JSON 文件存储；暂未提供多人协作、编辑历史或分布式写入。
- 模块是经过维护者审查的应用代码，具有主应用权限；没有不可信插件沙箱、在线代码上传或模块市场。
- 生命周期模块拥有独立 DOM、运行态和可选 WebGL 上下文。动画共用调度时钟，目前没有共享 GPU 渲染器；复杂场景应控制画布数量与像素密度。
- `load({ request, id, data })` 按实例加载，公开页也支持；同轮相同路径请求合并。公开模块的数据接口必须本身允许匿名访问。
- `meta.version` 是描述信息，不会自动触发数据迁移。服务器凭据也不能放入模块源码、默认数据或公开仓库。

`context.save()` 将内容与运行态分开：私人页写服务器草稿，编辑台保留本地待保存改动，实验台只改本次实验。公开页和公开预览不可保存；任何内容公开仍须手动发布。持久保存带全页 revision 检查，遇到其他窗口修改会报告冲突，不自动覆盖。

## 全站背景

登录后可在「外观设置」上传背景、恢复默认或改为纯色。背景独立于页面草稿和发布状态，保存在 `DATA_DIR/appearance.json` 与 `DATA_DIR/backgrounds/`，访客刷新后同步看到；明暗主题仍是设备偏好。部署备份需要保留整个 DATA_DIR。模块封面由模块自行管理，不随全站背景替换。普通页面只加载当前页使用的模块，编辑台和实验台加载全部模块。

服务器状态模块提供数值旁的常驻小趋势图，以及可切换指标和时间范围的大图。历史采集独立于浏览器，保留 24 小时原始数据和 7 天汇总，详情见 HTTP 接口参考和 README。
