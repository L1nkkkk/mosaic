# Mosaic · 拼页

用独立模块组合自己的展示空间。Public 公开页、Private 私人页与编辑台共用模块渲染器，由服务端控制数据范围。

内置开场介绍、手记、连接清单、服务器状态、Bot 状态、代理节点、待办清单、WebGL 色场、天气、音乐、书单、访客来源和照片卡片。可以增加、拖动排序、隐藏、拖动调整大小和移除模块，在宽屏、窄屏预览中切换 Public / Private 范围。

## 界面与外观

0.7 使用精简的统一侧边导航、深色半透明模块与山景背景；主页、私人页、编辑台和实验台共用外观。手机上导航收进抽屉，模块按实际空间换行。

顶栏可以搜索当前页面的模块并切换明暗。搜索保留模块实例，清空搜索后交互状态仍在；明暗偏好只影响当前设备。

Public 页面始终使用访客视图：不显示私人空间、编辑台、实验台和外观管理入口，也不占用侧边栏空间，保留搜索与明暗切换。站点主人通过 `/private` 登录管理，已登录时访问 Public 也保持相同展示。

在私人空间登录后打开侧边「外观设置」，可上传 JPG / PNG / WebP 背景、恢复默认或改用纯色。背景立即在全站生效，访客刷新页面后可见，不需要发布模块草稿。原图最大 12 MB，浏览器自动缩至最长边 1920 像素并压缩为最多 512 KiB 的静态 WebP；服务器保留当前及上一张背景。设置与图片保存在 DATA_DIR，随现有数据目录备份，不影响模块内容。模块自己的封面保持独立。

默认背景从 1.88 MB 压缩到约 192 KB；普通页面只加载当前使用的模块，编辑台和实验台加载完整目录。静态文件使用 ETag 复用缓存，上传背景采用内容哈希地址和长期缓存。首次 HTML 已包含背景设置，无需额外请求后才显示。

原有模块、顺序和手动尺寸保持不变；没有宽度覆盖的介绍、链接、手记采用 4 / 12 列推荐宽度，窄屏自动扩大。瀑布流仍在编辑台的「页面排列」选择。天气、音乐和书单等额外内容由后续独立模块提供。

## Public 与 Private

- `/`（也可用 `/public`）：访客只收到已发布、允许展示的 Public 模块。即使已经登录，这个入口也不会返回 Private 内容。
- `/private`：登录后查看全部已保存模块，包括 Public、Private 和暂时隐藏的模块；尚未发布的内容也可以在这里查看。
- `/lab`：登录后独立测试模块、宽高、模拟资源、只读模式与动画状态；实验内容不写入网站。
- `/edit`：编辑模块及其显示范围。新模块默认 Private，原有 0.1 版本的公开模块保持 Public。

点击保存后，私人页读取新内容。把模块改为 Private 并保存，会立即撤下对应的公开内容；把模块改回 Public 后，需要再次发布才会对访客显示。服务器状态和 Bot 状态固定为 Private，服务端拒绝将它们设为 Public。

显示范围与内容草稿保存在同一份数据中。Private 模块同时保留 `visible: false` 的兼容标记，以免旧版读取器忽略新增范围字段。升级后新增的模块类型需要部署对应代码才能读取，回退前请检查数据兼容性。

## 本地运行

需要 Node.js 24。应用没有第三方运行依赖，也不需要数据库服务。

```sh
node scripts/setup.js
node --env-file=.env server/index.js
```

第一次设置会生成 `.env` 并显示管理密码；不会覆盖已有配置。打开 `http://localhost:3000/`，编辑台在 `/edit`。`.env`、`data/` 不会提交到 Git。

```sh
npm test
npm run check
```

滚动位置、实例生命周期、WebGL、交互保存和实验台的浏览器回归检查：安装 Chrome / Chromium 后运行 `npm run test:browser`。测试使用临时数据和独立浏览器配置，不连接生产站点；自定义浏览器路径可设置 `CHROME_BIN`。

## 模块约定

推荐新增 `modules/<id>/definition.js`、`client.js` 和 `style.css`，无需改核心中的模块列表：

- `definition.js` 导出 `meta` 和纯函数 `validate(data)`；仅此入口会在服务端执行。
- `client.js` 导出 `mount(context)`、`edit({ data, change })`；可选导出 `load({ request, id, data })` 与重导出的 `validate`。
- `mount()` 同步返回实例：`update(data, resource)`、`resize(size)`、`setActive(active)`、`frame(time, delta)` 和 `dispose()` 均可按需实现。核心按实例 ID 复用 DOM，刷新、排序和缩放不会重新挂载。
- `context.save(nextData)` 显式保存内容：私人页保存到服务器草稿，编辑预览更新未保存草稿，公开页只读，实验台只更新实验内容。临时输入、画布和动画状态留在实例闭包里。
- `meta.animation: 'continuous'` 可订阅共享动画时钟，离屏、后台和暂停时停止；减少动态效果偏好下只做按需绘制。
- `meta.isolation: 'shadow'` 可选样式隔离。模块仍是可信代码，Shadow DOM 不构成安全沙箱。

已有 `index.js` 的 `meta / validate / render / edit / load` 契约继续兼容；`render()` 的内部 HTML 在数据变化时仍可能替换，复杂交互应迁移至 `mount()`。服务端定义不引用浏览器入口，客户端可独立使用 DOM 和 WebGL。详细接口、复制模板和三个层级的示例见[模块开发手册](docs/MODULES.md)。

核心负责模块发现、编排、登录、草稿与发布，不理解单个模块的字段。部署前请确保现有内容使用的模块仍存在；改变已有模块的数据结构时需要兼容旧数据或显式迁移。

## 尺寸与自适应排布

模块声明尺寸需求，核心分配位置和宽度，模块通过自身样式适应分配到的空间。Public、Private 和编辑台预览使用同一套排布逻辑，依据网格的实际宽度计算，而不是只看浏览器窗口大小。调整容器宽度时只重新排布，不修改内容、顺序或保存的宽度偏好。

```js
export const meta = {
  // 其他模块信息……
  layout: {
    span: 4,          // 建议占 12 列中的 4 列，即三分之一行
    minWidth: 280,    // 希望至少有 280 CSS 像素宽
    aspectRatio: 16 / 9, // 可选；省略则高度随内容
  },
};
```

| 字段 | 约定 |
| --- | --- |
| `span` | 1～12 的整数，默认 6；3 / 4 / 6 / 8 / 12 分别表示四分之一、三分之一、半行、三分之二、整行。 |
| `minWidth` | 0～4096 的有限数值，默认 280；决定空间不足时何时扩大占列数。它是舒适宽度，容器比它更窄时仍占整行，模块内部需要继续适应。 |
| `aspectRatio` | 可选，宽除以高，范围 0.1～10；只约束内容框，不包含 Private 范围标签。框内内容过长时滚动，保留键盘访问；自动刷新保留模块内的滚动位置。 |

默认使用声明的占列数。不满足最小宽度时，依次提升到更大的 2、3、4、6、12 列档位。例如四分之一行的模块会逐渐变成三分之一行、半行、整行。默认按行换行，保留用户顺序；可在编辑台切换瀑布流，将下一模块放到能容纳它的最低位置，窄屏退为单列。DOM 和键盘顺序始终按内容数组保留。

编辑台的「模块宽度」可以选择推荐宽度或常用比例，也可以直接拖动卡片右下角改变宽度和高度。覆盖值保存在页面实例的 `layout: { span?, height? }`：`span` 为 1～12 的整数；可选 `height` 为 120～1600 的整数 CSS 像素，不包含编辑工具和范围标签。手动高度优先于模块的默认宽高比；省略高度则恢复随内容或模块比例变化。模块声明的最小宽度仍然生效，窄屏自动扩大占列数，不修改保存的偏好。核心只调整外框，模块自行适应内容区，内容过长时提供滚动。

左侧列表和预览卡片的 `⠿` 手柄都可拖动排序。右下角缩放手柄将宽度吸附到 12 列网格，高度按 8 像素吸附；只横向拖动会保留自动高度。接近屏幕边缘时页面自动滚动，松手提交到本地草稿，按 Esc 或取消触摸则恢复原状。后台状态刷新不会打断正在拖动的手柄。Public 预览的拖动使用模块 ID 定位，不会删除隐藏的 Private 模块。

手柄支持鼠标、触摸和键盘：排序手柄用方向键前后移动、Home / End 移到首尾；缩放手柄用左右键调整占列数、上下键调整高度。也可以在模块编辑窗口的「尺寸、外观与显示范围」里输入尺寸。「模块高度」留空恢复自动高度，「恢复推荐尺寸」清除当前模块的宽高覆盖。保存更新私人页，公开页仍需发布。旧模块的 `layout: 'wide'` / `'half'` 继续兼容，旧内容没有实例尺寸字段时直接使用模块推荐值。

模块管理自己的展示 DOM，推荐单个 `<article>` 作为根元素；核心提供内容框、圆角与布局容器。内部样式使用专属类名和 `@container` 查询适应模块宽度，避免给根元素写死宽度。手动高度或固定比例的内容框同时支持宽度、高度容器查询，模块可据此切换紧凑样式；自动高度的外层容器只提供宽度查询。固定比例模块也应限制内部图片、画布等元素尺寸，长内容可在内容框内滚动。声明错误会使模块检查或候选部署失败，不会静默改成其他尺寸。

尺寸约定和排布集中在 `web/layout.js`，编辑手势集中在 `web/arrange.js`；新增模块无需修改排布代码或接入拖拽事件。核心不缩放模块文字，也不改变模块内部结构。运行 `npm test && npm run check` 可验证尺寸、内容保存、Public / Private 隔离及模块约定。0.4 版本的手动高度需由 0.4 或更新版本读取；回退到早期版本前请恢复更新前的数据备份。

## 私人状态模块

`deploy/collect-status.py` 在宿主机上每 30 秒采集一次 CPU、内存、磁盘、运行时间，以及 AstrBot / NapCat 进程、QQ 登录和消息连接状态。它读取现有配置完成本机状态查询，仅输出数字、布尔值和采集时间；不会输出登录凭据、环境变量、聊天内容或日志。

网页容器只读挂载 `/var/lib/mosaic/monitor` 到 `/status`，不接触 Docker 管理接口或 bot 配置。受登录保护的 `/api/private/status` 再按字段白名单输出结果。采集失败时显示未知，超过 90 秒未更新时明确标记数据过期。

现有服务器上一次性安装状态采集：

```sh
sudo install -d -m 755 /usr/local/lib/mosaic /var/lib/mosaic/monitor
sudo install -m 644 deploy/collect-status.py deploy/status-history.py /usr/local/lib/mosaic/
sudo install -m 644 deploy/mosaic-status.service deploy/mosaic-status.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl start mosaic-status.service
sudo systemctl enable --now mosaic-status.timer
```

同时更新宿主机的 `mosaic-update` 脚本，让后续容器带上只读状态目录。已有页面可在编辑台添加这两个状态模块，保存后私人页即可显示。新建站点自带这两个 Private 模块。默认采集适配名为 `astrbot`、`napcat` 的容器，以及本机 6185 / 6099 端口；其他安装可调整采集脚本。独立部署或本地预览没有采集文件时，状态模块会显示等待采集。

## 数据与登录

`DATA_DIR/content.json` 同时保存草稿和发布版本，使用原子替换写入；保存带版本检查，两个编辑窗口不会静默覆盖。现有文件损坏时应用拒绝启动，不会自动清空内容。隐藏的模块不会进入公共内容接口。

单管理员密码使用 scrypt 哈希。会话签名、12 小时有效、HTTPS 下使用 Secure Cookie，写入请求校验来源，登录有速率限制。更换密码时同时轮换 `SESSION_SECRET` 以使已有会话失效。请通过备份文件恢复历史内容；第一版没有编辑历史和多人协作。

配置项：`PUBLIC_ORIGIN`（只包含协议与域名/端口）、`BASE_PATH`（可选，例如 `/mosaic`）、`ADMIN_PASSWORD_HASH`、`SESSION_SECRET`、`DATA_DIR`、`STATUS_FILE`（默认 `/status/status.json`）、`PORT`、`HOST`。生产容器监听内部网络，由 HTTPS 反向代理提供访问。

## GitHub → 自有服务器

1. 推送到 `main` 后，GitHub Actions 在 Node 24 容器内运行测试。
2. 测试通过后发布 `ghcr.io/l1nkkkk/mosaic:<commit>` 和 `:main` 镜像。首次发布后，确认 GitHub Packages 的容器包为 Public，并能匿名拉取；镜像不包含任何运行密钥或内容数据。
3. 服务器的 `mosaic-update.timer` 约每分钟检查一次公开镜像。候选版本先用内容副本检查模块兼容性和启动状态，再替换主容器；健康检查失败时恢复旧容器。切换时可能有几秒不可用。
4. `/var/lib/mosaic/data` 独立挂载，因此代码更新保留草稿与展示内容。服务器保留最近 5 次更新前的本地内容备份，以及上一容器用于回退。本地备份不能替代异地备份。

Actions 使用当前任务的 GitHub 自动令牌发布包；服务器只读取公开镜像，GitHub 中无需保存服务器登录私钥。

一次性服务器安装（需要 Docker、curl、systemd、flock）：

```sh
sudo install -d -m 700 /etc/mosaic /var/lib/mosaic
# 将私密配置写入 /etc/mosaic/app.env，权限 600；不要把它放在公开仓库。
sudo install -m 755 deploy/update.sh /usr/local/sbin/mosaic-update
sudo install -m 644 deploy/mosaic-update.service deploy/mosaic-update.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl start mosaic-update.service
sudo systemctl enable --now mosaic-update.timer
```

`/etc/mosaic/deploy.conf` 可覆盖 `IMAGE`、`APP_DIR`、`NETWORK`、`BASE_PATH`、`PORT`、`ENV_FILE`，同样仅允许 root 写入。默认 Docker 网络 `astrnet` 必须已存在；反向代理将 `/mosaic/*` 原样转发到 `mosaic:3000`。管理应用的 `BASE_PATH` 必须与更新脚本相同。

容器默认限制为 0.5 CPU、192 MiB 内存；只读根文件系统，以普通用户运行，日志最多 10 MiB。构建发生在 GitHub，服务器负责下载和运行。

基础运行镜像在 `Dockerfile` 中固定了摘要，普通代码更新可以复用服务器已有镜像层。如果首次从 GHCR 下载基础层较慢，可先用服务器已有的 Docker Hub 加速源拉取 `Dockerfile` 中指定的 `node:24-alpine@sha256:...` 镜像。更新运行时摘要时，也应先测试并准备相同基础层。

检查更新和运行状态：

```sh
sudo systemctl status mosaic-update.timer
sudo journalctl -u mosaic-update.service -n 30
sudo docker inspect mosaic --format '{{.State.Health.Status}}'
```

手动回退前先停用自动更新，再将当前容器停止、移除并把 `mosaic-previous` 重命名为 `mosaic` 后启动。回退镜像保留当前内容；数据结构发生不兼容变化时，应同时从更新前备份恢复内容。修复 `main` 并发布后再启用更新计时器。

0.5 新增持久实例、实验台、`flow` 排列和 `appearance` 外观字段。切回旧版前恢复更新前备份；旧版不认识新模块类型。编辑台可选择「无边框」，核心去除常见卡片装饰，模块内部响应式布局仍由模块负责。

## 服务器历史趋势（0.8）

服务器状态模块采用任务管理器式布局：CPU、内存、网络数值旁常驻最近 1 小时的小折线图，点击指标切换旁边大图；窄卡片将大图排在下方。小图保持实时，大图可独立暂停和浏览历史。大图范围为最近 1 小时、6 小时、24 小时和 7 天。可暂停实时更新、查看前后区间、回到实时；鼠标或触摸查看数值，键盘左右方向键查看采集点。模块按容器宽度调整图表，隐藏时暂停历史请求和绘制，重新可见时补取数据。没有持续动画循环。

宿主机原有采集服务写入 `/var/lib/mosaic/monitor/history.sqlite`，保留 24 小时约 30 秒的原始记录，以及 7 天的 30 分钟汇总。6 小时视图按 1 分钟、24 小时视图按 5 分钟汇总。平均值绘为曲线，最小 / 最大值绘为细线，保留短时峰值。采集失败、超过 90 秒的采集间隔会标记缺口；网络只统计 IPv4 默认路由网卡的收发字节，首次采样、重启、接口更换或计数器重置时不推算速率。

历史仅保存数字和时间，数据库通过现有 `/status` 挂载只读提供给网页容器；不需要开放端口或安装新依赖。Python 标准库负责写入，固定版本 Node 24 自带 SQLite 负责读取。历史从启用后积累，不生成过去的数据。更新容器不会清空历史；备份时除 DATA_DIR 外，如需保留历史可用 Python `sqlite3.Connection.backup()` 备份此数据库。

首次启用需要同时安装两个采集脚本；只推送网页镜像不会升级宿主机采集脚本。原有状态快照在历史写入失败时仍继续生成。测试：`npm test`、`python3 -m unittest discover -s test -p '*_test.py'`、`npm run test:browser`。


## 画布编辑（0.9.1）

编辑台使用整页画布，不显示常驻导航或模块列表侧栏。点击模块内非交互区域，或卡片上的「编辑」，打开当前模块的编辑窗口。音乐、输入框、链接、图表等交互区域保留原有操作，统一的编辑按钮始终可用。完成或按 Esc 关闭窗口会返回画布并保留滚动位置；不会重新创建其他模块实例。

内容字段优先展示，尺寸、外观和显示范围收在可展开设置中。窗口内「保存草稿」保存全部本地改动；「完成编辑」只关闭窗口，仍需在顶部保存或发布。发布规则和 Public / Private 权限不变。

模块多时用「查找模块」按模块类型或标题搜索，包含隐藏和 Private 模块。选择结果会定位卡片并打开编辑；公开预览中找到私人模块时会切回全部预览。拖动排序与角落缩放、键盘手柄继续可用。新增模块直接打开编辑窗口，默认仅自己可见。空间名称和排列方式移到顶部「页面设置」，返回「我的页面」可进入全站外观设置。

## 生活模块（0.9）

已有站点更新后，在编辑台选择「＋ 添加」。新增实例默认 Private 且未发布，配置后保存即可在私人页查看；要给访客展示，改为 Public、打开显示并发布。部署只增加可选模块，不替换现有页面内容或背景。

| 模块 | 配置与行为 |
| --- | --- |
| 天气 | 搜索并选择城市，显示当前天气、体感、湿度、风速和三日预报；不请求访客定位。服务端按坐标缓存 10 分钟。 |
| 音乐播放器 | 最多 12 首；填写曲名、音乐人，上传音频或使用 HTTPS 音频直链，可上传唱片封面。可识别网易云歌曲链接；支持原生播放、音量、进度与前后选曲，自动播放默认关闭。刷新模块、排序、缩放保持当前播放；离开页面停止。 |
| 书单 | 最多 16 本；填写书名、作者、推荐语、阅读状态、可选链接，上传封面。没有封面时使用书名封面。 |
| 照片卡片 | 上传图片、标题、配文、图片描述和可选链接；可调整垂直裁切位置与文字遮罩。 |
| 访客来源 | 公开发布后开始统计公开页；只放在 Private 时不采集。显示今日估算访客、累计访问及近 30 天国家/地区分布；无历史数据时从零开始。 |

图片接受 JPG / PNG / WebP 原图（≤ 12 MB），浏览器压缩为 ≤ 512 KiB 的静态 WebP。音频支持 MP3 / WAV / OGG / FLAC，单文件 ≤ 20 MiB，总素材空间 96 MiB。浏览器对图片延迟加载、音频不预加载；格式能否播放也取决于浏览器。直链必须直接返回音频，不是音乐服务的分享页面。私人外链音频受原站权限控制，Mosaic 只能保护自己上传的素材。

素材保存到 `DATA_DIR/media`，备份时与 `content.json` 一起保留。上传后仍需保存草稿；下次上传时清理超过 24 小时且未被草稿或发布内容引用的素材。公开素材可直接读取；私人素材每次读取都验证会话，不使用浏览器持久缓存，支持音频 Range 分段播放。公开转私人并保存会撤回后续匿名请求，已被访客下载的文件无法收回。

天气来自 [Open-Meteo](https://open-meteo.com/)，城市来自其 Geocoding API，卡片保留来源署名。当前使用免费非商业接口，适用于个人无广告站点；商业化时依据[服务条款](https://open-meteo.com/en/terms)更换适合的服务。应用限制天气与城市合计每小时 300 次、每天 5000 次上游请求，失败至少缓存 1 分钟；接口不可用时显示失败，不生成虚假天气。

访客统计位于 `DATA_DIR/visitors.sqlite`，使用 Node 自带 SQLite，没有常驻后台采集任务。登录主人的访问不计入，尊重 DNT / GPC，不设置追踪 Cookie。同一天按 IP 与浏览器特征的 HMAC 估算独立访客，30 秒内重复访问去重，因此不是精确人数，也不用于计费。原始 IP 不写入统计数据库；国家查询时会传给 [ipwho.is](https://ipwhois.io/documentation)，仅保留国家代码，内存缓存不保留明文 IP。地区查询每天至多 900 次、同时至多 4 个；失败或超额归入未知。地图为示意，列表列出访问量前五的国家/地区。

日汇总保留 90 天，累计访问数长期保留；下一次读取或采集时清理过期数据和以前日期的每日标识。每天最多记录 10000 个独立标识，达到上限后忽略新的标识。需由可信反向代理追加/覆盖 `X-Forwarded-For`（读取最后一项），应用端口不要直接暴露；独立本地运行使用连接地址。IP 地区会受代理、共享网络影响，浏览器隐私设置和脚本拦截也会影响计数。


## 网易云与播放设置（0.10）

在音乐模块的编辑窗口粘贴 `https://music.163.com/song?id=歌曲编号`，点击「识别并加入歌单」，会填写曲名、歌手与封面；同一网易云歌曲再次导入会更新原条目，不重复添加。也支持 `/#/song?id=` 和 `y.music.163.com/m/song?id=`。不解析歌单或任意短链接。分享参数会移除，仅保存歌曲编号。旧内容把这种链接填在音频栏时，会自动按歌曲编号读取，不再把网页当作音频。封面由网易云图片域名直接提供，自己上传的封面优先。

歌单内「提前 / 后移」调整实际顺序。播放模式有：顺序播放（末尾停止）、列表循环、单曲循环、随机播放（多首时不立即重复当前歌曲）。切换模式、重排、缩放和页面数据刷新不会重置当前音频。播放中切换歌曲会继续播放，暂停时切歌保持暂停；随机模式下上一首优先回到播放历史。模式选择在编辑窗口保存，访客不会改写站点设置。

「进入网页时尝试自动播放」默认关闭，只对展示页生效，编辑台与实验台保持安静。受[浏览器自动播放策略](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)限制，开启也不能保证每位访客自动听到音乐；遇到 `NotAllowedError` 显示点击播放，不伪装为已播放，不借助其他点击强行启动。多个音乐模块最多自动启动一个，主动播放另一模块会暂停先前模块。离开页面停止播放。

元信息读取网易云自己的歌曲详情接口，音频使用其公开外链播放入口；不使用账号 Cookie、会员解析或第三方解锁服务。服务端只获取元信息和跳转地址，不下载或转发整首音频。跳转地址必须属于网易云音乐 CDN，并升级为 HTTPS，以免 HTTPS 站点播放 HTTP 音频失败。地址有时效，播放失败时可重新尝试。即便能识别歌名，也不保证外链可播；版权、地区、平台策略和网络可能影响播放，失败时保留「在网易云打开」和上传音频选择。

元信息缓存 6 小时，播放地址缓存 1 分钟，合计最多 60 次上游查询 / 分钟。展示页通过站内只读接口按当前歌曲请求，不为整张歌单预取音频，也不会在每次状态刷新时重新请求播放地址。这些平台接口不是本站控制的稳定契约，变更时会降级显示错误。
